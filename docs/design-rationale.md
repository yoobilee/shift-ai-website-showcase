# Design Rationale

## 핵심 가설

홈페이지 제작 시스템이 같아도 업종의 사업 목적과 사용자의 결정 방식이 다르면 화면의 구조와 행동 유도 역시 달라야 합니다.

## 아이웹 관찰에서 출발한 개선 방향

1. 여러 개의 고정 버튼을 우하단의 단일 Utility Dock으로 통합해 첫 화면 점유를 줄였습니다.
2. 동시에 겹치는 공지 대신 한 번에 한 공지만 읽는 Unified Notice Dialog를 설계했습니다.
3. 색과 이미지 교체를 넘어 정보 밀도, 그리드, 타이포그래피, 이미지 비율, CTA와 모션 리듬을 업종별로 분리했습니다.
4. 안정적인 기업 홈페이지 구조를 유지하면서도 Apple의 단계적 정보 공개, Toss의 명확한 행동 언어, Linear의 밀도 제어, Stripe의 제품 설명 방식을 원칙 단위로 참고했습니다.

특정 사이트의 외형을 복제하지 않고 `무엇을 먼저 보여 주고 어떤 행동으로 연결할지`를 판단 기준으로 삼았습니다.

## 공통 시스템과 변주 범위

공통으로 재사용하는 것은 업종 상태, 미리보기 장치 상태, 브라우저 프레임, 접근성 규칙, 공지와 빠른 메뉴입니다. 업종별로 분리하는 것은 페이지 구조, 그리드, 타입 스케일, 색 역할, 이미지 크롭, 섹션 순서와 CTA 문구입니다.

이 구분 덕분에 제작 속도를 확보하면서도 세 사이트가 하나의 템플릿처럼 보이는 문제를 피합니다.
