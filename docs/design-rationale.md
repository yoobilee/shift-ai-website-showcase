# Design Rationale

## 핵심 가설

홈페이지 제작 시스템이 같아도 업종의 사업 목적과 사용자의 결정 방식이 다르면 화면의 구조와 행동 유도 역시 달라야 합니다.

## 아이웹 관찰에서 출발한 개선 방향

1. 바깥 포트폴리오 소개와 브라우저 프레임을 제거해 업종별 홈페이지 경험이 첫 화면의 주인공이 되게 했습니다.
2. 화면 가장자리의 Utility Dock과 중복 공지를 제거하고, 업종·테마·보기·설명을 58px 높이의 공통 도구 모음에 통합했습니다.
3. 프로젝트의 제작 의도와 AI 검토 과정은 탐색을 가리지 않는 단일 설명 drawer로 이동했습니다.
4. 색과 이미지 교체를 넘어 정보 밀도, 그리드, 타이포그래피, 이미지 비율, CTA와 모션 리듬을 업종별로 분리했습니다.
5. 안정적인 기업 홈페이지 구조, 단계적 정보 공개, 명확한 행동 언어와 밀도 제어를 특정 사이트 외형이 아닌 원칙 단위로 참고했습니다.

특정 사이트의 외형을 복제하지 않고 `무엇을 먼저 보여 주고 어떤 행동으로 연결할지`를 판단 기준으로 삼았습니다.

## 공통 시스템과 변주 범위

공통으로 재사용하는 것은 업종·테마·보기 상태, URL과 저장 규칙, 상단 도구 모음, 프로젝트 설명과 접근성 로직입니다. 업종별로 분리하는 것은 페이지 구조, 그리드, 타입 스케일, 의미 색 토큰, 이미지 크롭, 섹션 순서와 CTA 문구입니다.

이 구분 덕분에 제작 속도를 확보하면서도 세 사이트가 하나의 템플릿처럼 보이는 문제를 피합니다.

## 이번 구조 변경의 판단 근거

- 전체 화면을 기본값으로 삼아 실제 홈페이지처럼 스크롤하고 링크를 탐색하도록 했습니다.
- 업종은 공유 가능한 URL 상태로, 테마와 보기 모드는 서로 독립적인 UI 상태로 관리합니다.
- 선택 탭의 배경만 transform으로 이동하고 콘텐츠는 짧은 opacity 전환만 사용해 도구 모음 위치가 흔들리지 않게 했습니다.
- 산업기술 화면은 장식보다 텍스트와 수치가 우선되도록 최소 글자 크기, 대비, 표면과 그룹 간격을 보강했습니다.
- 라이트·다크 테마는 색상 반전이 아니라 업종별 배경·표면·글자·강조·경계 역할을 다시 정의했습니다.

## 목적 중심 모션

모션은 피드백, 상태 표시, 공간적 연결과 갑작스러운 전환 완화에만 사용합니다. 업종 선택기의 활성판 이동과 짧은 화면 진입은 공통으로 유지하고, 스크롤 reveal은 섹션 제목·대표 이미지·카드나 수치 그룹처럼 읽는 단위가 분명한 곳에 한 번만 적용합니다.

- VECTORON은 기술 카드와 수치 그룹을 빠르게 노출해 정보 확인 흐름을 방해하지 않습니다.
- MORU는 대표 이미지와 갤러리에 더 긴 opacity·clip reveal을 사용해 편집 디자인의 호흡을 유지합니다.
- BASKET DAY는 메뉴와 매장 카드에 짧은 stagger를 사용해 캠페인 리듬을 강조합니다.

기본 CSS 상태는 콘텐츠가 보이도록 두고, `IntersectionObserver`가 준비된 컨테이너에만 pending 상태를 적용합니다. 따라서 JavaScript 또는 observer가 실패해도 콘텐츠가 숨은 채 남지 않습니다. `prefers-reduced-motion: reduce`에서는 이동, clip-path, stagger와 화면 진입 애니메이션을 제거합니다.

## 메인과 대표 세부 페이지의 역할

메인은 업종의 목적과 전체 흐름을 빠르게 파악하는 탐색 화면으로 두고, 구매·상담·방문 결정에 더 많은 맥락이 필요한 대표 사례만 고유 경로의 세부 페이지로 확장했습니다. 메인 헤더는 기존 섹션 앵커를 유지하므로 한 페이지 탐색의 속도를 잃지 않습니다.

- VECTORON의 VNX-400은 성능 수치, 사양표와 도입 단계를 가까이 배치해 비교·구매 검토에 필요한 근거를 우선합니다.
- MORU의 Serene House는 큰 이미지와 비대칭 갤러리, 재료와 설계 과정을 느슨한 편집 리듬으로 연결해 작품 감상을 우선합니다.
- BASKET DAY의 Tomato Picnic은 메뉴 구성, 가격, 판매 기간과 매장을 강한 카드 리듬으로 이어 소비자의 방문 결정을 우선합니다.

경로 판별과 History API 탐색, 공통 도구 모음은 재사용하되 세 페이지의 마크업을 하나의 범용 템플릿으로 합치지 않았습니다. 기존 WebP 자산을 다른 비율과 크롭으로 재사용해 새 이미지 생성 없이 각 상세 맥락을 구성했습니다.
